Finding currency arbitrage with Bellman–Ford

Currencies are vertices. Each quote is a directed edge with weight −log(rate). A round trip that makes money is a cycle whose rates multiply to more than 1, which is exactly a cycle of negative total weight. Bellman–Ford finds negative cycles.

Arbitrage
r₁·r₂·…·rk > 1
Take −log of both sides

Each vertex shows its current Bellman–Ford distance. Every vertex starts at 0, as if a virtual source pointed at all of them with weight 0.

Run the algorithm

  1. Rounds 1 to n−1: relax every edge. If u→v gives v a smaller distance, update it.
  2. Why n−1 rounds is enough: a shortest path never repeats a currency, so it has at most n−1 edges (graph handout, Problem 4a).
  3. Round n is the check. If any distance still drops, no shortest path exists, so there is a negative cycle. Follow the predecessor links back to recover it.

Rates are sample numbers for the demo, not live quotes. In the fair market every round trip loses the spread, so there is no negative cycle. Editing a cell switches to the Custom scenario.

Search: Bellman–Ford from a virtual source with early exit and a predecessor-cycle check. After each cycle is found, its tightest leg is removed and the search runs again (up to 8 cycles). Symbols whose USD price differs by more than 10% between venues are kept apart (same ticker, different token).

What the numbers leave out: the time it takes to send orders (prices move first), moving coins between exchanges for cross-venue cycles, minimum order sizes, and anything beyond the best price level. Real opportunities are rarer and smaller than this.
